# Учёт аренды опалубки

Статическое веб-приложение: каталог опалубки, склад, сделки аренды и автоматический
расчёт стоимости. Валюта — сомони (`с.`). Данные хранятся в браузере устройства
(`localStorage`), сервер и база не нужны.

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | Всё приложение: разметка, стили, логика |
| `manifest.webmanifest` | Описание PWA (имя, иконки, цвета) |
| `sw.js` | Удаляет старый офлайн-кэш на устройствах, где он остался. Не удалять |
| `icon-192.png`, `icon-512.png` | Иконки для главного экрана |
| `apps-script/Code.gs` | Скрипт для Google Таблицы — вставляется в таблицу, на сайте не исполняется |

Все четыре вспомогательных файла должны лежать **рядом** с `index.html`.

## Проверка на телефоне до публикации

В папке проекта:

```powershell
python -m http.server 8080
```

Узнайте IP компьютера (`ipconfig`, строка IPv4) и откройте на телефоне в той же
Wi-Fi-сети `http://<IP>:8080`.

## Google Таблица — общая база

Без таблицы данные лежат только в браузере устройства. С таблицей она становится
общей базой: несколько человек с разных устройств видят одни и те же сделки и склад,
а на каждом устройстве хранится копия, с которой приложение работает сразу.

```
приложение (копия)  ⇄  Apps Script (веб-приложение)  ⇄  Google Таблица
```

### Подключение

Подключение вшито в код: `BUILTIN_SHEET` в `index.html`. Пароля нет. Когда вписан
адрес таблицы, каждое устройство подключается само при открытии — вводить ничего
не нужно, только своё имя (один раз, для истории сделок).

Создать таблицу — один раз, с компьютера, около 5 минут:

1. Создайте новую Google Таблицу: <https://sheets.new>.
2. «Расширения» → «Apps Script». Удалите всё в редакторе и вставьте код из
   [`apps-script/Code.gs`](apps-script/Code.gs) как есть. Ctrl+S.
3. «Развернуть» (Deploy) → «Новое развертывание» → шестерёнка → «Веб-приложение».
   «Запуск от имени» — **Я**, «У кого есть доступ» — **Все**. «Развернуть».
4. Разрешите доступ: ваш аккаунт → «Дополнительно» → «Перейти на страницу…» →
   «Разрешить». Предупреждение «приложение не проверено» — нормально, скрипт ваш.
5. Скопируйте «URL веб-приложения» (заканчивается на `/exec`) и впишите его в
   `BUILTIN_SHEET.url` в `index.html`, затем опубликуйте сайт.

При первом подключении устройства: таблица пустая — туда выгружаются данные
с него; на устройстве нет сделок — берутся данные из таблицы; сделки есть и там,
и там — приложение спросит, что оставить, и перед заменой скачает резервную копию.

Если `BUILTIN_SHEET.url` пустой, подключение работает по-старому: адрес вводят
вручную в «Ещё» → «Google Таблица».

### Как это работает

* Изменения уходят в таблицу в фоне, через полсекунды после сохранения. Чужие
  подтягиваются при открытии, при возвращении в приложение и раз в 30 секунд.
* Без интернета приложение работает с копией; индикатор в шапке показывает
  «Нет связи», изменения отправятся, когда связь появится.
* Если двое изменили данные почти одновременно, правки сливаются по сделкам,
  позициям и отдельным полям: один записал оплату, другой — возврат по той же
  сделке, сохранятся оба. Если одно и то же поле изменили по-разному или выдали
  со склада больше, чем есть, приложение покажет предупреждение.
* Листы «Каталог», «Сделки», «Возвраты», «История» обновляются сами — их можно
  смотреть, фильтровать и печатать, но **правьте данные только в приложении**:
  ручные правки в листах перезаписываются. Сами данные — в скрытом листе `_data`.

### Безопасность

**Пароля нет, а адрес таблицы вшит в код публичного сайта и публичного репозитория.**
Любой, кто откроет код страницы, может прочитать все данные в таблице, включая
имена и телефоны клиентов, а также изменить или стереть их.

Если нужно закрыть доступ: создайте новое развертывание (`clasp deploy` без `-i`),
впишите его адрес в `BUILTIN_SHEET.url`, а старое удалите
(`clasp undeploy <id>` или «Развернуть» → «Управление развертываниями»).
Регулярно делайте экспорт — «Ещё» → «Экспорт в файл», — чтобы было что восстановить.

### Обновление скрипта

Скрипт загружается через [clasp](https://github.com/google/clasp): `.clasp.json` в корне
указывает на проект таблицы, код — в папке `apps-script/`. Из корня проекта:

```bash
clasp push --force
clasp deploy -i AKfycbyPpC8OZwomUfi89sH09A5n71M-XPOMD8213WoFyyqbq7NZ3wHUkLNBxFPkdrAnB3xu -d "описание"
```

Второй командой обновляется существующее развертывание, поэтому адрес, вшитый
в `index.html`, остаётся прежним. Новое развертывание (`clasp deploy` без `-i`)
дало бы новый адрес.

Если в манифесте `apps-script/appsscript.json` менялись права (`oauthScopes`),
владельцу таблицы нужно один раз открыть редактор скрипта, выбрать функцию
`authorize` → «Выполнить» и разрешить доступ.

## Резервные копии

Без Google Таблицы данные лежат только в браузере того устройства, где вы их
вводили. Очистка данных сайта или переустановка браузера их сотрёт.

Меню «Ещё» → **Экспорт в файл** сохраняет всё в один `.json`.
Если копии не было больше двух недель, приложение само напомнит жёлтой плашкой.
**Импорт из файла** восстанавливает данные (полностью заменяя текущие).

## Каталог

Базовый каталог (29 позиций: дамкраты, щиты, леса, мешалка, карита, бочка)
задан в `index.html` в массиве `DEFAULT_CATALOG`. При первом запуске версии
с новым `CATALOG_VERSION` приложение один раз заменяет им каталог на
устройстве; сделки при этом не трогаются. Вернуть базовый каталог вручную:
«Ещё» → «Загрузить базовый каталог».

Размер у позиции необязателен: ширина × высота для щитов, одна длина для
дамкратов, без размера — для лесов, мешалки и т. п. Единица — штуки или
комплекты.

## Как считается стоимость

Каждый щит оплачивается за дни, которые он был у клиента, **но не больше срока
по договору**:

```
дни щита = min(срок по договору, max(1, дата возврата − дата выдачи))
сумма    = Σ (штук × цена за штуку в день × дни щита)
```

* Вернули раньше срока — платят только за фактические дни (минимум 1 день).
* Вернули позже срока — платят как по договору, доплаты за просрочку нет.
* Ещё не вернули — считаются по сроку договора. Поэтому сумма активной сделки
  может только уменьшиться.

Пример: 10 шт × 10 дней по 5 с. = 500 с. по договору. 4 шт вернули на 5-й
день, 6 шт — на 13-й: 4×5×5 + 6×10×5 = **400 с.**

Если после раннего возврата сумма стала меньше оплаченного, в сделке
появляется «переплата — вернуть клиенту».

Цена фиксируется в момент создания сделки: изменение тарифа в каталоге не
пересчитывает уже оформленные аренды. Залог в сумму аренды не входит — он
возвратный и учитывается отдельно.

## Частичный возврат

Кнопка «Возврат» у активной сделки открывает форму: дата и сколько штук каждой
позиции привезли (по умолчанию — 0; кнопка «Всё» отмечает всё, что на руках). Вернули часть — сделка
остаётся активной, в списке видно «вернул 4 из 12», щиты сразу свободны на
складе. Вернули последние — сделка закрывается сама.

Все возвраты видны в «Изменить» → «Возвраты». Ошибочный можно удалить — щиты
снова будут числиться на клиенте, закрытая сделка откроется. Удалить нельзя,
если эти щиты уже выданы другому клиенту.

## История сделки

Значок часов со стрелкой в карточке сделки открывает её историю — от выдачи до
закрытия, по порядку, с датой и временем: выдача, каждое изменение в виде
«было → стало», оплаты, возвраты, отмены возвратов, закрытие и повторное открытие.
Записи хранятся в самой сделке (`log`) и попадают в экспорт.

У сделок, заведённых до появления истории, она восстановлена по известным
данным — выдача, возвраты, закрытие — и помечена «восстановлено». Их прошлые
правки не записывались.

## Ограничения

* Нельзя выдать больше штук, чем свободно на складе.
* Нельзя уменьшить количество в каталоге ниже того, что сейчас в аренде.
* Нельзя удалить позицию каталога, пока она в аренде.
* В сделке нельзя указать меньше штук, чем клиент уже вернул.
* Продления срока и пени за просрочку нет.
